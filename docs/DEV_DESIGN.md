# 主机厂售后反馈报告工作台开发设计

## 1. 技术栈

- Vite + React + TypeScript
- 普通 CSS
- 本地 TS mock 数据
- 规则分析函数
- 后续接 LLM 报告生成层

第一版先不接真实第三方问卷 API，不做数据库，不做登录权限。

## 2. 页面结构

### 页面一：问卷字段说明

目的：说明车主反馈如何通过第三方问卷平台低摩擦收集，以及每个字段如何进入后续分析。

模块：

- 售后服务体验反馈字段
- 字段必填 / 可选
- 字段后续用途
- 填写率优化
- 隐私与授权提示

### 页面二：售后反馈报告工作台

目的：把问卷导出结果整理成运营可用报告。

操作路径：

1. 选择业务项目和来源文件，先确定本次分析的数据池。
2. 在已选项目内设定分析时间与地区范围。
3. 查看诊断结论、重点关注和指标解释。
4. 选择专项输出，复制总报告或专项清单。

## 3. 工作台信息架构

### 顶部步骤定位器

- 是工作台主路径，不是审批流程。
- 点击步骤可回退到对应工作区。
  - 每一步展示当前状态：
  - 业务项目：已选择的业务项目、来源文件和项目数据覆盖周期。
  - 分析范围：已设定的报告日期、全国 / 区域 / 城市 / 服务中心范围。
  - 诊断与指标：当前样本是否可查看分析。
  - 报告与原话：当前范围是否可复制报告并展开证据。

### 步骤一：业务项目数据池

顺序定义：先选业务项目，再选分析时间。原因是业务项目决定要合并哪些问卷来源和样本；项目自带“数据覆盖周期”，但最终报告时间范围需要在下一步按周报、专项活动或复盘会议口径单独设定。

- 导入问卷结果
  - Excel / CSV 上传入口
  - 业务项目列表
  - 项目下来源文件列表
  - 标准导入模板字段清单
  - CSV 模板下载入口
  - 模拟导入批次
  - 项目名识别说明
  - 时间范围识别说明
  - 字段映射说明
  - 导入后校验面板：基于当前项目来源文件实时计算项目一致性、来源数量、时间范围、必填字段、指标覆盖和隐私风险

### 步骤二：分析范围

- 项目与时间
  - 开始日期
  - 结束日期
  - 清除服务中心筛选
- 反馈池
  - 当前统计范围
  - 区域 / 城市 / 服务中心筛选器
  - 当前范围指标
  - 服务中心下钻后的原始评论列表

### 步骤三：诊断与指标

- 建议报告
- 重点关注
  - 好区域典型清单：最多展示 3 个可复制服务中心 / 区域
  - 风险区域典型清单：最多展示 3 个需处理服务中心 / 区域
  - 每张卡片展示代表样本数、当前范围样本数、共性、动作和证据原话
- 专项指标卡
- 主题归因卡
- 证据原话
- 处理动作

### 步骤四：报告与专项输出

- 专项复盘选择
  - 服务问题闭环
  - 满意度归因
  - 区域 / 城市下钻
  - 活动体验复盘
  - 口碑素材与风险
  - 每个专项按钮展示输出内容摘要，不只展示名称。
  - 左侧交付类型面板展示适用对象、使用场景和输出内容，和右侧报告区组成同一个交付工作区。
- 售后体验总报告
- 专项报告或专项清单
- 报告关键指标条：反馈量、平均服务评分、净推荐值、低分反馈、待跟进。
- 每个关键指标后提供轻量问号标签，用于解释指标口径。
- 纯数据复盘区：
  - 体验结果：平均服务评分、净推荐值、满意率
  - 问题风险：低分反馈、负向占比、口碑风险
  - 闭环处理：待跟进、联系授权率、需人工复核
  - 范围覆盖：反馈量、覆盖城市、覆盖服务中心
- 报告段落
- 闭环任务卡：对象、问题、动作、时限、回访口径
- 可展开证据原话
- 复制按钮

### 回退逻辑

- 每一步底部都有上一步 / 下一步。
- 顶部步骤可直接回到任意已配置步骤。
- 诊断页可返回修改项目或修改时间 / 地区。
- 报告页可返回诊断，也可回到范围筛选重新生成。

## 4. 数据流

```txt
Excel / CSV 导出
-> 字段映射
-> 导入校验
-> 按业务项目合并多来源文件
-> FeedbackImportRecord
-> 日期 / 项目 / 服务中心筛选
-> MetricSummary
-> FocusRegionInsight
-> AnalysisFinding
-> ScenarioOutput
-> 页面展示和复制
```

## 5. 模块职责

### SurveyTemplatePreview

展示问卷字段和字段用途，不负责真实问卷投放。

### WorkbenchShell

管理项目、日期、服务中心、专项复盘状态，并把当前范围数据传给各模块。

步骤一会调用导入校验规则，针对当前业务项目下的全部来源文件生成“已通过 / 需确认 / 存在异常”的校验结果。这里不能只展示说明文案；只要 UI 写“校验”，就必须来自数据计算。

### FeedbackPool

展示当前统计范围、区域 / 城市 / 服务中心层级、当前指标和原始评论。

大样本下，FeedbackPool 不默认渲染全部原话；只展示当前范围指标、地区筛选、风险网点和服务中心下钻后的有限评论列表。生产版需要分页或虚拟列表。

### AnalysisWorkspace

展示建议报告、重点关注、专项指标、主题归因和证据原话。

### ScenarioOutputPanel

展示总报告和专项输出，支持复制和展开证据。总报告用于管理层复盘摘要；服务问题闭环专项以待办清单展示，不再渲染成普通报告段落。

### analysisRules

负责规则归因、指标计算、重点关注识别、日期筛选和服务中心下钻。

### importValidation

负责导入后校验：

- 业务项目一致性
- 来源文件数量与样本量
- 提交时间推断范围
- 必填字段完整性
- 服务评分 / 推荐意愿评分 / 地区字段覆盖
- 明文手机号、VIN、车牌、地址等隐私风险检测

### outputTemplates

负责把结构化分析结果转成可复制报告。

## 6. 后续必须补齐

- Excel / CSV 文件解析。
- 字段映射确认 UI。
- 导入结果确认弹窗。
- 原始评论分页或虚拟滚动。
- 后台异步解析和报告缓存，用于月度数万级反馈。
- 报告导出。
- LLM 报告生成接口占位。

## 7. 设计原则

- 按运营步骤组织，而不是堆功能。
- 先给建议报告，再给专项下钻。
- 每个分数都要解释来源。
- 每个结论都要能展开证据原话。
- 原始评论必须可追溯到项目、日期、服务中心和问卷来源。
- 不把 Dashboard 当作 MVP 主入口。
- 不把提效比例作为用户界面卖点。
