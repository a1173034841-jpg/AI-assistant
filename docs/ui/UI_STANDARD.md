# 售后反馈工作台 UI 标准

## 目标

将原型界面统一为专业、克制、高密度的售后运营控制台。界面优先服务运营团队的扫描、筛选、判断、下钻和复制报告，不做营销化展示。

## 设计原则

- **结构先于装饰**：页面先清楚表达工作流、当前范围、关键指标和交付内容，再考虑视觉强化。
- **对齐可预测**：同一层级的标题、说明、按钮、标签和数字必须基线一致，避免文字偏移和卡片高度跳变。
- **状态可见**：按钮、筛选项、步骤、复制、下载、追问都必须有 hover、focus、active、disabled 或反馈状态。
- **动效克制**：动效只用于状态变化和点击反馈，时长控制在 160-240ms，并尊重 `prefers-reduced-motion`。
- **数据密度友好**：运营工具不使用大面积空装饰；指标、筛选、报告块保持紧凑但不拥挤。
- **证据可追溯**：任何报告结论、指标和原话展开都应在视觉上属于同一证据体系。

## 视觉方向

- 风格：数据密集型运营控制台。
- 主色：深墨蓝承载结构，服务青绿承载主操作和通过状态。
- 状态色：红色用于风险，琥珀用于需确认，绿色用于通过或正向。
- 背景：浅冷灰工作区，白色/微灰表面，减少纯绿色铺底造成的单调感。
- 圆角：常规卡片、按钮、输入框使用 8px；小标签使用 999px；不使用大圆角卡片。

## Token 规范

### 颜色

- `--color-bg`：页面背景。
- `--color-surface`：主表面。
- `--color-surface-muted`：次级表面。
- `--color-text`：主文字。
- `--color-text-muted`：说明文字。
- `--color-border`：边框。
- `--color-primary`：主操作、激活态。
- `--color-accent`：次操作、链接和强调。
- `--color-success` / `--color-warning` / `--color-danger`：状态表达。

### 间距

- 基础节奏为 4px / 8px。
- 控件内边距常用 8、12、16。
- 卡片内边距常用 16、20。
- 页面区块间距常用 16、24。
- 禁止随意新增 11、13、17、19 等无体系间距。

### 字体

- 中文界面保持系统中文字体栈，避免远程字体依赖。
- 正文不小于 13px；主要正文推荐 14px。
- 工具内标题不使用 hero 级字号；核心页标题 28-34px，面板标题 16-20px。
- 数字可使用系统等宽数字能力，保持指标列对齐。

### 阴影与边框

- 普通卡片使用 1px 边框和轻阴影。
- 激活状态优先使用边框、背景和文字色，不靠大阴影。
- 风险/通过/警告卡片使用左侧状态条或状态标签，避免整块高饱和背景。

## 组件标准

### 页面壳

- 顶部标题区必须说明产品身份、当前使用场景和隐私边界。
- 主内容区最大宽度固定在控制台可读范围内，宽屏居中。
- 页脚只保留与当前原型有关的隐私和数据说明。

### 步骤条

- 每个步骤为等高按钮，内部使用标题、状态、描述三行。
- 激活态、已完成态、普通态要明确区分。
- 文本必须单行截断，不允许挤压到按钮外。

### 面板

- 统一使用 `.panel` 表达容器。
- 面板标题区使用 `.panel-heading`，包含 eyebrow、标题、说明和可选操作。
- 不在面板中再嵌套外观像大卡片的页面区块；内部重复项可以是 `.data-card`。

### 控件

- 主按钮使用 `.button-primary`；次按钮使用 `.button-secondary`；危险或风险操作使用状态色。
- 图标按钮必须有 `aria-label` 或可见文本。
- 所有按钮最小点击高度 36px；关键操作和移动端按钮不低于 44px。
- 输入框、文本域和日期选择必须有清晰 focus ring。

### 筛选项

- Chip 高度统一为 36px，文字左、数量右。
- 激活态不得改变布局尺寸。
- 长文本使用省略号，数量保持不换行。

### 指标

- 指标卡使用统一网格，数字行使用等宽数字。
- 单位与数字同一基线，单位弱化。
- 指标口径说明用 `details` 或带 `title` 的帮助按钮，不额外占用主阅读层级。

### 报告与证据

- 总报告使用主报告样式，专项报告使用普通报告样式。
- 闭环任务使用结构化行：标签列固定宽度，内容列自适应。
- 证据原话使用浅底和左边状态条，保持可追溯但不抢主报告层级。

## 响应式标准

- 1440px：工作台展示为多列，优先显示筛选、指标和报告。
- 1024px：多列降为两列或单列，保持步骤条两列。
- 720px 以下：步骤条、筛选项、指标和报告全部单列；按钮不并排挤压。
- 任何视口不得出现页面级横向滚动。
- 表格类内容在移动端改为卡片/行块，不强制宽表格。

## 动效标准

- 常规 hover / active / focus 过渡：160-220ms。
- 只过渡 `background-color`、`border-color`、`color`、`box-shadow`、`transform`、`opacity`。
- 按压反馈可使用 `translateY(1px)` 或轻微阴影变化，不影响周围布局。
- 禁止慢速装饰动画和循环背景动画。
- `prefers-reduced-motion: reduce` 下关闭非必要过渡和 transform。

## 可访问性标准

- 正文对比度不低于 WCAG AA。
- Focus ring 必须可见。
- 不用颜色作为唯一状态信息，状态卡同时提供文字标签。
- 文本按钮和图标按钮必须有可读名称。
- 表格语义、`aria-label` 和 `details/summary` 保持可键盘操作。

## 本次重构验收清单

- 顶部、步骤条、范围摘要、面板标题、按钮和筛选项视觉系统一致。
- 文字不出现明显偏移、上下不对称、按钮内不居中或卡片高度突跳。
- 核心页面在 375px、768px、1024px、1440px 逻辑上可读。
- 动效轻、快、可预测，并支持 reduced motion。
- `npm run build` 和 `npm test` 通过。
