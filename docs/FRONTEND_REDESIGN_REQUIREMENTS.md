# 售后反馈连续复盘与分析工作台前端重设计需求文档

版本：2026-06-10  
对象：前端 / UI / UX 设计师  
范围：重设计现有桌面 Web 工作台的信息架构、页面布局、视觉层级、Logo、组件状态和关键交互。不包含后端、AI 接口和数据库设计。不做移动端。

## 1. 项目背景

这是一个面向新能源主机厂售后运营团队的反馈分析工作台。

它不替代问卷星、腾讯问卷、App 问卷或售后回访系统，而是承接这些渠道导出的售后反馈，把车主原话整理成运营团队能直接使用的复盘报告、问题清单、口碑素材、风险摘要和可追溯证据。

一句话解释：

> 问卷负责把车主声音收进来，这个工具负责把车主声音变成运营能用的材料。

本次重设计不是做一个更漂亮的 dashboard，而是把现有原型整理成一个清晰、高效、可信、对齐稳定的桌面售后反馈工作台。

## 2. 本次修正目标

当前 UI 的主要问题不是功能缺失，而是信息架构、筛选逻辑、AI 问答入口和设计执行没有收住：

- 左侧仍像流程导航，不像功能型工作台。
- 对齐混乱：顶部栏、左侧导航、主面板、右侧证据、KPI 底边、表格列宽没有统一基线。
- 文案不面向用户：不能出现 `Agent`、`Final 屏`、`Stitch 历史版本` 等内部语言。
- Logo 缺失或不成熟：需要一个能表达产品定位的正式标识。
- 筛选逻辑不直观：项目、区域、城市、服务中心需要像 Excel 一样横向筛选，并且区域 > 城市 > 服务中心必须层级联动。
- AI 问答区过小：输入区和问答内容需要更适合连续提问。
- 按钮缺少交互状态：很多元素看起来能点，但没有选中、处理、成功或禁用反馈。

设计完成后，用户应该能完成：

1. 新建项目并导入问卷 Excel / CSV 数据。
2. 查看过往所有项目、导入批次和报告状态。
3. 在报告仪表盘按项目、日期、区域、城市、服务中心筛选。
4. 根据筛选范围查看总报告、专项报告、指标和证据。
5. 从报告仪表盘中选中数据后发起浮动 AI 问答，或直接进入 AI 问答开启新对话。
6. 在个人中心查看个人设置、账号状态、隐私与数据。

## 3. 信息架构

左侧导航必须改为功能划分，而不是旧的工作流程。一级导航为：

1. 新建项目
2. 查看项目
3. 报告仪表盘
4. AI 问答
5. 个人中心

采用桌面工作台两级导航：

- 一级导航固定承载功能分区。
- 二级导航展示当前功能下的具体入口。
- 用户刚进入网页且没有点击任何一级导航时，右侧必须显示 `工作台首页 / 最近工作区`，展示最近项目、待处理导入、近期报告和可继续问答；二级导航必须隐藏。
- 未点击一级导航时，右侧不能默认展示 `新建项目`、`报告仪表盘` 或任何二级功能页，也不能留白。
- Hover 一级导航只能预览一级导航文字和说明，不能打开二级导航，不能刷新右侧内容。
- 只有 Click 一级导航后，才打开该一级下的二级导航，并进入默认二级页面。
- 一级导航展开时显示标题和说明。
- 一级导航折叠时保留图标和 active 状态。
- 当前一级聚焦时，二级导航只展示该一级下的入口。
- 点击一级或二级导航后，一级导航自动收起；只有手动点击展开按钮或 hover 展开按钮时才临时展开。
- 折叠态顶部不要显示产品文字或遮挡式 Logo，只保留清晰的展开控制和一级图标。
- 折叠交互参考 Supabase：主布局宽度保持稳定，一级导航通过浮层预览展开；hover 时不允许按钮位置移动、页面宽度跳变或闪烁。
- 折叠态采用稳定 56px 一级图标栏 + 232px 浮层预览；预览只能覆盖一级栏，不得推动二级导航或主工作区。
- 点击二级导航必须刷新完整三级工作区，不能只替换标题、右侧小卡片或局部说明。
- `字段映射`、`导入校验`、`生成初始复盘`、`导入历史`必须分别是不同的主工作页面。
- `AI 问答 / 新建问答`默认强调大输入区和新会话；`AI 问答 / 问答历史`默认强调历史记录、收藏和继续问答；两者不能看起来完全一样。
- `报告仪表盘` 的二级页也必须完整刷新：`总览` 只展示当前范围、核心指标和下一步；`时间维度` 只展示时间粒度和具体周期；`项目维度` 只展示项目范围和项目比较；`区域维度` 只展示区域、城市、服务中心三级联动；`问题主题` 只展示主题风险和反馈原文；`报告输出` 进入报告正文和专项报告。

二级导航建议：

| 一级导航 | 二级导航 |
| --- | --- |
| 新建项目 | 上传反馈数据、字段映射、导入校验、生成初始复盘、导入历史 |
| 查看项目 | 全部项目、最近项目、项目详情、导入批次、归档项目 |
| 报告仪表盘 | 总览、时间维度、项目维度、区域维度、问题主题、报告输出 |
| AI 问答 | 新建问答、问答历史 |
| 个人中心 | 个人设置、账号状态、隐私设置、数据权限 |

注意：

- “收藏问答”不是二级导航，收藏通过问答历史项右侧星标完成。
- “服务中心下钻”不要作为重复入口；服务中心在筛选区选中后应立即应用。
- “报告仪表盘”不是泛 Dashboard 首页，而是业务维度分析、筛选、报告和证据工作区；证据原话只作为报告、指标详情和问答结果的支撑内容，不作为左侧二级入口。
- 证据原话在仪表盘中应通过“查看反馈原文 / 收起反馈原文”显式打开，不能缩在角落里成为静态装饰。

## 4. 当前页面范围

最终只做桌面界面，不做移动端。需要覆盖以下 7 个桌面状态：

0. 工作台首页 / 最近工作区：未点击一级导航时的默认状态，二级导航隐藏。
1. 新建项目 / 导入与校验
2. 查看项目
3. 报告仪表盘 / 筛选与维度下钻
4. 报告仪表盘 / 报告与专项输出
5. AI 问答
6. 个人中心

不要设计：

- 移动端。
- 手机端。
- 390px 版本。
- 移动底部导航。
- 营销落地页。
- 登录 / 注册页。
- Stitch 文档屏或过程说明页。
- 与产品无关的项目管理页或模板页。

## 5. 品牌与 Logo 需求

产品全称：`售后反馈连续复盘与分析工作台`  
界面短名：`售后复盘工作台`

功能命名：

- `AI 问答`，不要写 `Agent 追问`。
- `数据查询结果`，不要写 `Agent 回答`。
- `问答记录` 或 `查询记录`，不要写 `Agent 记录`。
- `发送查询`，不要写 `发送追问`。

Logo 核心概念：`声音 -> 证据 -> 决策`。

图形结构建议：

- 外框：深墨蓝圆角方形，表达工作台、稳定和企业级。
- 内部：青绿色对话气泡轮廓，表达车主反馈。
- 内部：三根数据柱，表达反馈被结构化、聚合和比较。
- 右下：小型通过勾，表达校验通过、证据链闭环和结论可追溯。

颜色：

- 深墨蓝：`#0F172A`
- 青绿色：`#008B8B`
- 浅青 / 白色：`#A7F3D0` / `#FFFFFF`
- 通过绿：`#38A169`

禁止：

- AI 星光、发光、渐变球。
- 车辆剪影。
- 复杂插画。
- 纯剪贴板图标。
- 过度圆润的 mascot 风格。

## 6. 筛选与仪表盘逻辑

筛选功能要更接近 Excel：

- 横向分组展示筛选器。
- 多选项点击后立即应用。
- 已选项有清晰 selected 状态。
- 可再次点击取消选择。
- 每组都有“全部 / 清空”状态。
- 长字段自动换行或拆成标题、元信息、数量三层，不挤压到一行。
- 时间筛选必须是“粒度 + 具体周期”。选择“日”要展示具体日期，选择“周”要展示具体起止日期，选择“月 / 季度 / 年”要展示具体周期，选择“自定义”要展示可编辑开始日期和结束日期。
- “月 / 季度 / 年”也必须展示真实起止范围，例如 `2026-05-01 至 2026-05-31`、`2026-04-01 至 2026-06-30`、`2026-01-01 至 2026-12-31`，不能只显示抽象标签。

项目范围：

- 默认全部项目。
- 可选择单项目。
- 可选择多项目。
- 可取消选择回到全部项目。
- 每个项目必须显示名称、类型、时间范围和反馈量。
- 项目维度页必须让当前导入表里的全部项目首屏可见，避免用户误以为项目缺失。

区域层级：

- 区域是父级。
- 城市是区域的子级。
- 服务中心是城市的子级。
- 选区域后才显示对应城市。
- 选城市后才显示对应服务中心。
- 切换上级时自动清理不合法的下级选择。
- 区域维度页必须让区域列表首屏可见；城市和服务中心未满足父级条件时，用清晰空状态提示“先选区域 / 先选城市”。

问题主题：

- 主题选择区必须横向铺开，不能只占半屏留下大块无意义空白。
- 主题选择后要刷新风险对象、反馈原文和当前范围摘要。

下一步动作：

- “进入报告输出”必须按当前筛选范围生成报告。
- “进入 AI 问答”必须按当前筛选范围提问。
- 直接从左侧导航进入 AI 问答时，默认开启新问答，不强制套用范围。

## 7. AI 问答逻辑

AI 问答打开后默认落在“新建问答”，同时展示问答历史。

必须支持：

- 新建对话。
- 套用当前筛选范围。
- 参考项目选择和取消选择。
- 历史记录打开和关闭。
- 直接从左侧导航进入时，清空上一次仪表盘带入的问题和范围，默认自由新问答。
- 从仪表盘进入时，只把范围和问题注入本次新对话，不反向修改仪表盘筛选。
- 推荐问题填入输入框。
- 发送查询。
- 问答收藏星标。
- 保存当前问答。
- 生成问答摘要。
- 无关问题自然拒答。
- AI 问答三列必须顶部和底部对齐：左侧问答记录、中间主对话、右侧引用与操作同高。中间输入区优先保证宽度和高度，右侧引用证据必须可读、可滚动、不能横向截断。

报告仪表盘中的浮动 AI 问答：

1. 用户在报告仪表盘界面选中指定数据。
2. 选中后出现“AI 问答”按钮。
3. 点开按钮后显示轻量输入框。
4. 用户输入问题并发送。
5. 系统进入 AI 问答页面，自动创建一个问答会话，并带入刚才的范围和问题。

注意：这里的“项目”在 AI 问答中有两层含义，业务项目和问答会话必须区分，不能把问答会话写成“新项目”。

## 8. 全局布局要求

桌面端建议布局：

```txt
顶部全局栏
  Logo / 产品短名
  当前项目 / 时间范围 / 数据来源 / 样本量
  复制 / 导出 / 重新识别等全局动作

左侧两级导航
  一级功能分区
  当前一级下的二级入口

主工作区
  当前页面的核心任务

右侧辅助区
  当前范围、证据、状态、下一步动作
```

对齐规则：

- 顶部栏使用三段网格，不要把所有信息挤在同一行。
- 左侧一级导航项高度一致，图标、标题、说明基线统一。
- 二级导航缩进一致，active 状态清楚。
- 主面板标题和右侧操作按钮同一基线。
- 所有页面的横向分栏都必须同高。
- 每一行的左列、中列、右列必须顶部对齐、底部对齐。
- 如果某列内部由多张卡片组成，外层使用纵向 flex stack，底部列表、证据、历史记录或查询结果自动填满剩余空间。
- 不允许大面积无意义空白；内容不足时使用历史、证据、查询结果、操作条或空状态补齐。
- 筛选器长字段必须拆成标题、元信息、数量三层显示，反馈量、时间范围、项目类型不能挤成一团。
- 个人中心这类多卡片页面不要做瀑布流错位；同一行卡片高度一致。
- KPI 卡底边对齐，卡片宽度一致。
- 表格列宽稳定，数字列右对齐或使用等宽数字。
- 右侧证据卡统一宽度、内边距和左侧状态色条。

## 9. 页面具体需求

### 9.1 新建项目 / 导入与校验

目标：让运营确认这批数据能否被正确分析。

必须包含：

- Excel / CSV 上传入口。
- 标准模板下载。
- 当前识别出的项目名称、来源平台、时间范围、样本量。
- 字段映射状态。
- 必填字段完整性。
- 指标字段覆盖率。
- 隐私字段检查。
- 历史导入记录。
- 校验通过、需确认、错误三类状态。

设计修正重点：

- 上传卡、字段映射表、右侧识别结果三列顶部对齐、底部对齐。
- 历史文件列表字号加大，文件名不要拥挤。
- 主按钮必须根据状态变化：上传、重新识别、继续筛选、修正文件。
- 校验异常不要像静态说明，必须像真实状态。

### 9.2 查看项目

目标：让运营查看过往所有项目。

必须包含：

- 全部项目列表。
- 最近项目。
- 项目详情摘要。
- 导入批次。
- 归档项目。
- 项目名称、项目类型、时间范围、反馈量、报告状态。

项目卡片和表格行必须可点击；首次点击是选择项目，再次点击取消选择。选中项目后才能执行“打开报告仪表盘”，并带入项目范围；未选项目时保持全部项目。

### 9.3 报告仪表盘 / 筛选与维度下钻

目标：让运营确定当前复盘范围，并找到需要处理的区域、城市、服务中心和证据。

必须包含：

- 横向筛选区。
- 当前范围摘要。
- 核心指标。
- 风险服务中心列表。
- 好区域典型和风险区域典型。
- 下一步动作：进入报告输出、进入 AI 问答。
- 浮动 AI 问答入口。

设计修正重点：

- 筛选区、指标区、右侧范围面板三列顶部对齐、底部对齐。
- 表格字号不低于 14px，建议 15px。
- 风险 badge 必须清楚，不只靠颜色。
- 服务中心不再重复做“下钻按钮”，选中即应用。

### 9.4 报告仪表盘 / 报告与专项输出

目标：让运营拿到可复制、可讲、可追踪的材料。

必须包含：

- 总复盘报告。
- 8 个报告模块：数据概览、整体体验、核心问题、时间 / 项目复盘、区域 / 城市 / 服务中心表现、用户原话证据、运营动作建议、可继续查询的问题。
- 专项报告入口：服务问题闭环、满意度归因、区域城市督查端、活动体验复盘、口碑投诉与风险。
- 专项报告选中态。
- 专项摘要预览。
- 证据原话。
- 复制报告、导出报告、复制问题清单、复制口碑素材等操作。

设计修正重点：

- 总报告视觉层级高于专项报告。
- 点击专项后，报告摘要和右侧内容必须变化。
- 证据必须与报告结论建立编号或引用关系。
- 报告正文不要留下大面积无意义空白。

### 9.5 AI 问答

目标：让运营围绕当前报告、指标、原话和范围继续提问。

必须包含：

- 本次对话上下文。
- 问答记录列表。
- 中央聊天区顶部的参考项目选择和取消。
- 历史记录打开和关闭。
- 推荐问题。
- 大尺寸输入框与发送查询按钮。
- 处理流程：整理范围、查找证据、生成结论、保存记录。
- 数据查询结果。
- 保存当前问答、生成问答摘要。

设计修正重点：

- AI 问答按聊天工具工作区组织：左侧历史，中间主要对话和大输入框，右侧只放本次回答相关引用和操作。中间区域要比旧版更宽，输入框更大。
- 历史记录和参考项目都必须支持再次点击取消，且只影响当前对话。
- 右侧不要再放与当前回答无关的“证据原话”装饰卡；证据只能跟回答或当前范围有关。

### 9.6 个人中心

目标：承载个人设置、账号状态、隐私设置和数据权限。

必须包含：

- 用户身份与权限概览。
- 账号状态。
- 数据权限。
- 导入历史摘要。
- 问答记录摘要。
- 隐私与数据说明。

不要显示“Supabase 数据接口”模块，也不要把具体后端平台作为功能模块。导入历史、问答记录、导出记录可以作为内容摘要或操作入口，不作为个人中心二级导航。

## 10. 字号与密度

桌面端关键字号下限：

- 页面标题：28-32px。
- 区块标题：18-20px。
- 正文和报告内容：15-16px。
- 表格：14-15px。
- 证据原话：15px，行高 23px 以上。
- 证据元信息：14px，行高 20px 以上。
- 按钮 / chip / badge：14px。
- 顶部全局信息：12px 标签 + 14px 数值。

高密度应通过网格、对齐、分组实现，不是把字缩小。

## 11. 交互状态要求

即使是静态设计，也必须表现以下状态：

- 左侧导航：active / hover / collapsed。
- 二级导航：active / hover。
- 项目卡片：active / hover / success。
- 筛选项：selected / unselected / disabled。
- 专项报告列表：selected，并显示对应专项摘要预览。
- 问答记录：打开 / 关闭 / favorite。
- 推荐问题 chip：点击后填入输入框。
- 发送查询：显示处理流程。
- 复制 / 导出 / 上传 / 重新识别：显示成功或处理中反馈。
- 空状态：告诉用户下一步操作。
- 错误状态：用自然语言说明，不像系统报错。
