# 主机厂售后反馈报告工作台开发设计

## 1. 技术栈

- Vite + React + TypeScript
- 普通 CSS
- 标准 CSV 测试数据 + 本地上传解析
- 规则分析函数
- 后续接 LLM 报告生成层

第一版先不接真实第三方问卷 API，不做数据库，不做登录权限。

## 2. 页面结构

### 标准 CSV 字段说明

目的：嵌入在导入区，说明第三方问卷导出的 CSV 应包含哪些字段，以及每个字段如何进入后续分析。

模块：

- 售后服务体验反馈字段
- 字段必填 / 可选
- 字段后续用途
- 填写率优化
- 隐私与授权提示

### 页面一：售后反馈报告工作台

目的：把问卷导出结果整理成运营可用报告。

操作路径：

1. 导入 CSV 并立即查看固定 8 模块自动复盘。
2. 在同一工作区筛选时间、项目集合、地区、城市和服务中心，并查看原始评论。
3. 生成模块化报告、专项输出，并通过 Agent 继续追问。

## 3. 工作台信息架构

### 顶部步骤定位器

- 是工作台主路径，不是审批流程。
- 点击步骤可回退到对应工作区。
  - 每一步展示当前状态：
  - 导入与自动复盘：字段校验状态和固定 8 模块复盘。
  - 筛选与下钻：已设定的时间、项目、全国 / 区域 / 城市 / 服务中心范围。
  - 报告与追问：当前范围是否可生成模块化报告并调用 Agent。

### 步骤一：导入与自动复盘

顺序定义：先导入数据，系统立即做字段校验和固定 8 模块自动复盘。运营先看到整体判断，再进入筛选。

- 导入问卷结果
  - CSV 上传入口
  - 业务项目列表
  - 项目下来源文件列表
  - 标准导入模板字段清单
  - CSV 模板下载入口
  - 标准 CSV 测试数据
  - 项目名识别说明
  - 时间范围识别说明
  - 字段映射说明
  - 导入后校验面板：基于当前项目来源文件实时计算项目一致性、来源数量、时间范围、必填字段、指标覆盖和隐私风险

### 步骤二：筛选与下钻

- 时间与项目
  - 开始日期
  - 结束日期
  - 日 / 周 / 月 / 季度 / 年 / 自定义时间段
  - 全部项目 / 单项目 / 多项目 / 项目类型
- 反馈池
  - 当前统计范围
  - 区域 / 城市 / 服务中心筛选器
  - 当前范围指标
  - 服务中心下钻后的原始评论列表

### 步骤三：报告与追问

- 建议报告
- 重点关注
  - 好区域典型清单：最多展示 3 个可复制服务中心 / 区域
  - 风险区域典型清单：最多展示 3 个需处理服务中心 / 区域
  - 每张卡片展示代表样本数、当前范围样本数、共性、动作和证据原话
- 专项指标卡
- 主题归因卡
- 证据原话
- 处理动作
- 专项复盘选择
  - 服务问题闭环
  - 满意度归因
  - 区域 / 城市下钻
  - 活动体验复盘
  - 口碑素材与风险
  - 每个专项按钮展示输出内容摘要，不只展示名称。
  - 左侧交付类型面板展示适用对象、使用场景和输出内容，和右侧报告区组成同一个交付工作区。
- 售后体验总报告
- 专项报告或专项清单
- 内置 Agent 追问
- LLM API 接口预留：当前使用本地规则 Agent，后续替换为真实 LLM 端口
- 报告关键指标条：反馈量、平均服务评分、净推荐值、低分反馈、待跟进。
- 每个关键指标后提供轻量问号标签，用于解释指标口径。
- 纯数据复盘区：
  - 体验结果：平均服务评分、净推荐值、满意率
  - 问题风险：低分反馈、负向占比、口碑风险
  - 闭环处理：待跟进、联系授权率、需人工复核
  - 范围覆盖：反馈量、覆盖城市、覆盖服务中心
- 报告段落
- 闭环任务卡：对象、问题、动作、时限、回访口径
- 可展开证据原话
- 复制按钮

### 回退逻辑

- 每一步底部都有上一步 / 下一步。
- 顶部步骤可直接回到任意已配置步骤。
- 报告页可返回筛选页修改项目、时间或地区。
- 报告页可返回诊断，也可回到范围筛选重新生成。

## 4. 数据流

```txt
Excel / CSV 导出
-> 字段映射
-> 导入校验
-> 按业务项目合并多来源文件
-> FeedbackImportRecord
-> 日期 / 项目 / 服务中心筛选
-> MetricSummary
-> FocusRegionInsight
-> AnalysisFinding
-> ScenarioOutput
-> 页面展示和复制
```

## 5. 模块职责

### CsvImportPanel

展示标准 CSV 字段、模板下载、文件上传和导入状态，不负责真实问卷投放。

### WorkbenchShell

管理项目、日期、服务中心、专项复盘状态，并把当前范围数据传给各模块。

步骤一会调用导入校验规则，针对当前业务项目下的全部来源文件生成“已通过 / 需确认 / 存在异常”的校验结果。这里不能只展示说明文案；只要 UI 写“校验”，就必须来自数据计算。

### FeedbackPool

展示当前统计范围、区域 / 城市 / 服务中心层级、当前指标和原始评论。

大样本下，FeedbackPool 不默认渲染全部原话；只展示当前范围指标、地区筛选、风险网点和服务中心下钻后的有限评论列表。生产版需要分页或虚拟列表。

### AnalysisWorkspace

展示建议报告、重点关注、专项指标、主题归因和证据原话。

### ScenarioOutputPanel

展示总报告和专项输出，支持复制和展开证据。总报告用于管理层复盘摘要；服务问题闭环专项以待办清单展示，不再渲染成普通报告段落。

### analysisRules

负责规则归因、指标计算、重点关注识别、日期筛选和服务中心下钻。

### importValidation

负责导入后校验：

- 业务项目一致性
- 来源文件数量与样本量
- 提交时间推断范围
- 必填字段完整性
- 服务评分 / 推荐意愿评分 / 地区字段覆盖
- 明文手机号、VIN、车牌、地址等隐私风险检测

### outputTemplates

负责把结构化分析结果转成可复制报告。

## 6. 后续必须补齐

- CSV 文件解析已接入；Excel 直读作为后续能力。
- 字段映射确认 UI。
- 导入结果确认弹窗。
- 原始评论分页或虚拟滚动。
- 后台异步解析和报告缓存，用于月度数万级反馈。
- 报告导出。
- LLM 报告生成接口占位。

## 7. 设计原则

- 按运营步骤组织，而不是堆功能。
- 先给建议报告，再给专项下钻。
- 每个分数都要解释来源。
- 每个结论都要能展开证据原话。
- 原始评论必须可追溯到项目、日期、服务中心和问卷来源。
- 不把 Dashboard 当作 MVP 主入口。
- 不把提效比例作为用户界面卖点。
