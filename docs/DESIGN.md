# 售后反馈连续复盘与分析工作台 DESIGN.md

版本：2026-06-10  
范围：仅桌面端 Web 工作台。不要生成移动端、手机端、390px 版本或移动底部导航。

## 1. 产品定位

这是面向主机厂售后运营团队的反馈数据分析、复盘报告生成和数据问答工作台。

产品承接问卷星、腾讯问卷、App 问卷、短信链接、企微链接等渠道导出的售后反馈，把评分、时间、项目、区域、城市、服务中心和车主原话整理成可判断、可下钻、可复制、可查询、可推动闭环的运营材料。

一句话：

> 问卷负责把车主声音收进来；本工作台负责把车主声音变成运营能判断问题、追踪趋势、推动闭环和交付报告的材料。

它是桌面工作台，不是营销页，不是泛 AI 展示页，也不是传统 dashboard 首页。

## 2. 当前信息架构

左侧导航已经从“工作流程”改为“功能划分”。全局导航采用桌面工作台两级结构：

- 一级导航：固定的功能分区。
- 二级导航：当前功能下的具体工作入口。
- 默认首页态：用户刚进入网页、还没有点击任何一级导航时，右侧显示 `工作台首页 / 最近工作区`，二级导航完全不出现。
- 默认首页态内容：最近项目、待处理导入、近期报告、可继续问答和最近工作入口。它不是某个功能页，也不是空白页。
- Hover 一级导航只预览一级导航标签，不打开二级导航，不刷新右侧内容。
- Click 一级导航才打开该一级下的二级导航，并进入该一级默认二级页面。
- 当用户聚焦一级导航时，一级导航优先展示；展开后显示当前一级下的二级导航。
- 点击一级或二级导航后，一级导航自动收起，避免占用主工作区宽度。
- 折叠状态采用稳定 56px 一级图标栏 + 232px 浮层预览，不允许因为 hover 改变主布局宽度，也不允许 hover 时按钮位置漂移或闪烁。
- 一级导航只通过手动展开按钮、展开按钮 hover/focus 或一级图标 hover/focus 预览展开；鼠标离开一级栏后再关闭预览，必须有短暂缓冲，避免闪烁。
- 折叠态保留一级图标和 active 状态；顶部不显示产品文字或遮挡式 Logo。
- 二级导航不是小卡片切换。点击二级导航后，右侧三级工作区必须完整刷新为该二级功能的页面内容。
- 例如：`新建项目 / 字段映射` 应整页展示字段映射表和保存动作；`新建项目 / 导入校验` 应整页展示导入质量校验；`AI 问答 / 新建问答` 和 `AI 问答 / 问答历史` 必须有明显不同的页面布局和默认状态。
- `报告仪表盘` 的二级页也必须完整刷新：`总览` 只展示当前范围、核心指标和下一步；`时间维度` 只展示时间粒度和具体周期；`项目维度` 只展示项目范围和项目比较；`区域维度` 只展示区域、城市、服务中心三级联动；`问题主题` 只展示主题风险和反馈原文；`报告输出` 进入报告正文和专项报告。

最终一级导航为 5 个：

1. 新建项目
2. 查看项目
3. 报告仪表盘
4. AI 问答
5. 个人中心

二级导航如下：

| 一级导航 | 二级导航 | 说明 |
| --- | --- | --- |
| 新建项目 | 上传反馈数据、字段映射、导入校验、生成初始复盘、导入历史 | 创建新的分析项目，完成导入与校验 |
| 查看项目 | 全部项目、最近项目、项目详情、导入批次、归档项目 | 查看过往所有项目、导入批次和报告状态 |
| 报告仪表盘 | 总览、时间维度、项目维度、区域维度、问题主题、报告输出 | 按业务维度查看指标、筛选范围、风险对象、报告和证据 |
| AI 问答 | 新建问答、问答历史 | 默认进入新问答，同时展示历史；收藏通过历史项星标完成 |
| 个人中心 | 个人设置、账号状态、隐私设置、数据权限 | 管理个人偏好、账号状态、隐私边界和数据权限 |

## 3. 当前桌面页面

本地项目是 React + Vite 单页应用，技术入口只有一个 `index.html`。设计交付不能按 Stitch 历史屏幕数量计算，而要按本地产品实际用户界面状态计算。

当前需要同步的桌面产品状态为 7 个：

0. 工作台首页 / 最近工作区：未点击一级导航时的默认状态，右侧显示可继续处理的工作，二级导航隐藏。
1. 新建项目 / 导入与校验
2. 查看项目
3. 报告仪表盘 / 筛选与维度下钻
4. 报告仪表盘 / 报告与专项输出
5. AI 问答
6. 个人中心

Stitch 中以下内容不计入最终产品页面：

- Markdown 文档屏，例如 `FRONTEND_REDESIGN_REQUIREMENTS.md`。
- `DESIGN.md` 文档屏。
- 同标题非当前版本的旧稿。
- 任意 mobile / phone / 390px / responsive mobile 版本。
- 仅为过程说明、历史版本说明或设计提示词生成的页面。

## 5. 关键业务逻辑

### 5.1 报告仪表盘筛选逻辑

筛选器必须更接近 Excel 的横向筛选方式，强调“选择即应用”。

必须包含：

- 时间粒度：日、周、月、季度、年、自定义。
- 时间粒度必须搭配具体周期选择，不能只显示抽象的“日 / 周 / 月”。
- 选择“日”后必须能看到具体日期，例如 `2026-05-18`。
- 选择“周”后必须能看到具体周范围，例如 `2026-05-08 至 2026-05-14`。
- 选择“月 / 季度 / 年”后也必须展示真实起止范围，例如 `2026-05-01 至 2026-05-31`、`2026-04-01 至 2026-06-30`、`2026-01-01 至 2026-12-31`。
- 选择“自定义”后必须是开始日期 + 结束日期输入，不允许伪装成三个固定快捷选项。
- 项目范围：全部项目、单项目、多项目、项目类型。
- 地区范围：区域、城市、服务中心。
- 当前范围摘要。
- 核心指标：反馈量、平均服务评分、NPS、满意率、低分反馈、负向占比、待跟进、授权率。
- 风险服务中心列表。
- 好区域典型和风险区域典型。
- 原始评论下钻入口。

层级规则：

- 区域是父级。
- 城市是区域的子级。
- 服务中心是城市的子级。
- 用户未选区域时，城市不可选，并提示“先选区域”。
- 用户未选城市时，服务中心不可选，并提示“先选城市”。
- 切换区域时，自动清除不属于该区域的城市和服务中心。
- 切换城市时，自动清除不属于该城市的服务中心。
- 服务中心按钮选择后立即应用，不再出现重复的“服务中心下钻”步骤。
- 项目维度页必须让当前导入表里的全部项目在首屏可见，至少显示项目名称、类型、起止时间和反馈量，避免用户误以为项目缺失。
- 区域维度页必须让区域列表在首屏可见，城市和服务中心未满足父级条件时用清晰空状态说明“先选区域 / 先选城市”。
- 问题主题页的主题选择区必须横向铺开，不能只占半屏留下大块无意义空白。

筛选后的下一步：

- 点击“进入报告输出”时，直接按照当前筛选范围生成对应报告。
- 点击“进入 AI 问答”时，带入当前筛选范围。
- 如果用户直接从左侧导航进入 AI 问答，默认是新建自由问答，不强制套用当前范围。

### 5.2 AI 问答逻辑

AI 问答是功能区，不是开放聊天娱乐页。

必须包含：

- 默认落在“新建问答”。
- 同屏展示问答历史。
- “新建对话”和“套用当前筛选范围”可以同时存在，不冲突。
- 用户可以把具体业务项目作为本次对话参考，也可以取消参考项目。
- 用户可以打开历史记录继续提问，也可以关闭历史记录回到新对话。
- 从左侧导航直接进入 AI 问答时，必须清空上一次从仪表盘带入的问题和范围，默认显示自由新对话。
- 从报告仪表盘进入 AI 问答时，只把当前范围注入本次新会话，不反向改动仪表盘筛选。
- 收藏问答通过历史项右侧星标完成，不单独作为二级导航。
- 推荐问题点击后填入输入框。
- 发送后展示处理流程：`整理范围 -> 查找证据 -> 生成结论 -> 保存记录`。
- 数据查询结果必须能说明引用了哪些范围和证据。
- 无关问题必须自然拒答：`这个问题超出了当前售后反馈数据范围，我只能回答已导入数据、指标、报告结论和反馈原文相关问题。`

报告仪表盘里的浮动 AI 问答：

1. 用户在报告仪表盘中选中指定数据，例如项目、区域、城市或服务中心。
2. 页面出现轻量浮动“AI 问答”按钮。
3. 点击后打开轻量输入框，用户输入问题并发送。
4. 发送后系统进入 AI 问答页面，自动新建一个问答会话，并带入刚才选中的数据范围和问题。

注意：这里的“项目”如果出现在 AI 问答上下文中，要分清业务项目与问答会话；不要把问答会话写成“新项目”。

## 6. 页面要求

### 6.1 新建项目 / 导入与校验

目标：让运营确认这批数据能否被正确分析。

必须包含：

- Excel / CSV 上传入口。
- 标准模板下载。
- 当前识别出的项目名称、来源平台、时间范围、样本量。
- 字段映射状态。
- 必填字段完整性。
- 指标字段覆盖率。
- 隐私字段检查。
- 历史导入记录。
- 校验通过、需确认、错误三类状态。

页面第一屏聚焦上传和校验结果，不堆报告内容。上传区、字段映射表、识别结果区必须顶部对齐、底部对齐。

### 6.2 查看项目

目标：让运营查看过往所有项目、导入批次、报告状态和最近打开项。

必须包含：

- 项目列表。
- 项目名称、项目类型、时间范围、反馈量、报告状态。
- 最近项目。
- 导入批次。
- 归档项目入口。
- 打开项目后进入报告仪表盘，并带入项目范围。

项目卡片和项目表格行必须可点击、可再次点击取消，有 hover / selected / success 状态。选中项目后才出现可执行的“打开报告仪表盘”动作；打开后报告仪表盘必须带入该项目范围。不要出现“新建项目”按钮来代替项目选择。

### 6.3 报告仪表盘 / 筛选与维度下钻

目标：让运营确定当前复盘范围，并能下钻到风险对象和证据。

必须包含横向筛选区、指标区、风险表格、当前范围和下一步动作。

筛选区、指标区、右侧范围面板必须在同一 grid 行里等高。项目、区域、城市、服务中心的长字段不能挤压到不可读；用稳定列宽、换行和元信息分层解决。

### 6.4 报告仪表盘 / 报告与专项输出

目标：输出可复制、可下钻、可追溯的运营报告。

必须包含：

- 总复盘报告，优先展示。
- 默认自动复盘 8 个模块：数据概览、整体体验、核心问题、时间 / 项目复盘、区域 / 城市 / 服务中心表现、用户原话证据、运营动作建议、可继续查询的问题。
- 专项报告入口：服务问题闭环、满意度归因、区域 / 城市督查端、活动体验复盘、口碑投诉与风险。
- 专项入口必须有选中态，点击后报告摘要和右侧内容同步变化。
- 证据原话：原话内容、评分 / NPS、提交时间、来源平台、城市 / 服务中心、服务场景、被选为证据的原因。
- 复制报告、导出报告、复制问题清单、复制口碑素材等操作。

总报告必须先于专项报告。证据必须支撑结论，不要变成装饰引用。

### 6.5 AI 问答

目标：让运营围绕当前报告、指标、原话和范围继续提问。

必须包含：

- 本次对话上下文：入口、参考项目、历史记录或新对话。
- 问答记录列表。
- 中央聊天区顶部的参考项目选择与取消选择。
- 历史记录打开与关闭。
- 推荐问题。
- 大尺寸输入框与发送查询按钮。
- 数据查询结果。
- 右侧与当前回答相关的引用证据、保存、摘要生成和可问内容。

AI 问答采用类似聊天工具的工作区：左侧为问答历史，中间为主要对话和大输入框，右侧为本次回答引用与操作。输入区域不能太小，中间聊天区必须明显宽于左右辅助栏，更适合连续输入。

### 6.6 个人中心

目标：承载个人设置、账号状态、隐私设置和数据权限。

必须包含：

- 用户身份与权限概览。
- 账号状态。
- 数据权限。
- 导入历史摘要。
- 问答记录摘要。
- 隐私与数据说明。

个人中心不承载报告正文，不承载指标下钻，不出现“Supabase 数据接口”或任何具体后端平台内部名称。导入历史、问答记录、导出记录可以作为个人中心内容区摘要或操作，不作为二级导航扩散。

## 7. 视觉语言

整体是专业、克制、高密度的桌面运营控制台。

颜色：

- 背景：浅冷灰 `#F8FAFC`。
- 面板：白色 `#FFFFFF` 或极浅灰 `#F9FAFB`。
- 结构色：深墨蓝 `#0F172A`。
- 主行动：青绿色 `#008B8B`。
- 风险：红色 `#E53E3E`。
- 需确认：琥珀色 `#DD6B20`。
- 通过 / 成功：绿色 `#38A169`。
- 边框：`#E2E8F0`。
- 次级文字：`#64748B`。

禁止使用：

- 大面积渐变。
- AI 光效。
- 装饰插画。
- 营销 hero。
- 手机端导航。
- 嵌套卡片堆叠。
- 过大的圆角。

## 8. 排版、网格与对齐

桌面端以 1440px 为主画布，内容区使用稳定网格：

- 顶部栏：三段式网格，左侧 Logo / 产品名，中间当前范围，右侧全局操作。
- 主体：左侧一级/二级导航 220-280px；主工作区 1fr；右侧辅助区 320-360px。
- 面板之间间距 16px 或 24px。
- 面板内边距 20px 或 24px。
- 所有间距使用 4px / 8px 基准。
- 卡片圆角不超过 8px。
- 按钮高度统一 38-42px。

字号下限：

- 页面标题：28-32px。
- 区块标题：18-20px。
- 正文和报告内容：15-16px。
- 表格和列表：14-15px。
- 证据原话：15px，行高不低于 23px。
- 证据元信息：14px，行高不低于 20px。
- 按钮 / chip / badge：14px。
- 顶部全局信息：12px 标签 + 14px 数值。

对齐硬规则：

- 顶部栏信息不能挤在一行混排，必须按三段网格对齐。
- 左侧一级导航项高度一致，图标、标题、说明基线统一。
- 二级导航缩进一致，active 状态清楚。
- 主区域面板标题和右侧操作按钮同一基线。
- 所有横向分栏页面都必须在同一 grid 行内拉伸到同高。
- 每个页面的左列、中列、右列必须顶部对齐、底部对齐；同一行内的面板底边必须落在同一水平线上。
- 如果某一列由多张卡片组成，外层必须使用 `display: flex; flex-direction: column; height: 100%` 或等效布局。
- 顶部摘要 / 状态卡可以固定高度，底部列表 / 证据 / 历史 / 查询面板必须自动填满剩余空间。
- 如果某一页面有多行卡片，必须使用一致的 row height 或明确的 grid 布局；不要做瀑布流。
- 不允许为凑满高度留下大面积无意义空白；如果内容不足，底部区域应由历史、证据、查询结果、操作条或空状态填充。
- 筛选器长字段必须拆成标题、元信息、数量三层显示；反馈量等关键数字不能被挤到不可读的位置。
- KPI / 指标卡底边对齐，数字列使用等宽或右对齐。
- 表格列宽稳定，状态 badge 不挤压文字。
- 右侧证据卡统一宽度、统一内边距、统一左侧状态色条。
- 证据元信息使用两列布局，不用小字堆成一行。

## 9. 组件与交互状态

所有看起来可点击的元素都必须有状态表达：

- 默认。
- hover。
- focus。
- active / selected。
- disabled。
- loading。
- success。
- warning。
- error。
- empty。

具体要求：

- 左侧一级导航和二级导航必须有 active / hover 状态。
- 项目卡片必须能选择和取消选择。
- 筛选项必须能选择和取消选择，状态要通过视觉证明。
- 专项报告入口必须有选中态，切换后展示对应摘要预览。
- 问答记录必须可打开、可关闭；参考项目必须可选择、可取消，且这些操作只影响当前对话。
- AI 问答中的参考项目、历史记录和套用范围只影响本次对话，不得改变报告仪表盘、查看项目或个人中心的状态。
- 推荐问题 chip 点击后填入输入框。
- 发送查询必须展示处理流程。
- AI 问答三列必须顶部和底部对齐：左侧问答记录、中间主对话、右侧引用与操作同高。中间输入区优先保证宽度和高度，右侧引用证据必须可读、可滚动、不能横向截断。
- 复制、导出、上传、重新识别必须有处理中或成功反馈。
- 空状态必须告诉用户下一步做什么。

## 10. 证据原话规范

证据原话不是左侧二级导航，也不是筛选器入口。它只出现在报告输出、指标详情、风险对象详情和 AI 问答结果中，用来支撑结论。

在报告仪表盘中，证据原话应作为当前筛选范围下的显式互动面板出现，例如“查看反馈原文 / 收起反馈原文”。问题主题页可以默认展开该面板。它不能缩在右下角成为不可发现的静态装饰，也不能混入“筛选与下钻”主筛选区。

证据原话必须完整展示：

- 原话内容。
- 评分 / NPS。
- 提交时间。
- 来源平台。
- 城市 / 服务中心。
- 服务场景。
- 被选为证据的原因。

证据视觉规范：

- 左侧使用 3-4px 状态色条。
- 原话正文 15px 以上，不压缩成灰色小字。
- 元信息使用两列网格。
- 与报告结论建立编号或引用关系。
- 不使用装饰性大引号替代真实证据结构。
