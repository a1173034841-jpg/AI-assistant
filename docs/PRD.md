# 主机厂售后反馈报告工作台 PRD

## 1. 产品名称

主机厂售后反馈报告工作台

## 2. 一句话定位

承接问卷星、腾讯问卷、App 问卷、短信和企微等渠道收集到的售后反馈，帮助运营团队按项目和日期生成有结论、有证据、有动作、可下钻原始评论的服务复盘报告。

## 3. 费曼式解释

车主说的是自然语言：等太久、解释不清、移动服务很方便、App 预约不顺、活动体验不错。

运营团队需要的是工作语言：这个项目在这段时间表现如何，哪个服务中心做得好，哪个服务中心要处理，分数为什么这样，原始评论能不能证明，下周谁要跟进。

这个产品就是中间的翻译层：

> 问卷负责把车主声音收进来，报告工作台负责把车主声音变成运营能交付的复盘材料。

## 4. 目标用户

### 区域运营

- 看项目周期内区域服务体验。
- 找表现好的区域和表现差的区域。
- 给管理层或区域会输出复盘报告。

### 服务运营 / 服务中心管理者

- 看低分和负向反馈。
- 找问题集中的服务环节。
- 推动服务中心回访、整改和下周追踪。

### 用户运营 / 社群运营

- 看活动和社群反馈。
- 总结亮点、不满点和下次优化动作。

### 品牌口碑 / 内容团队

- 找可沉淀的正向原话。
- 找可能扩散的负向风险。

## 5. 核心问题

### 问卷平台只负责收集，不负责运营加工

问卷星、腾讯问卷等平台能收集评分和开放题，但不能直接生成复盘报告、问题清单、重点关注和可追溯证据。

### 开放反馈难以直接使用

车主原话混合情绪、问题、建议、表扬和个案，运营需要把它们整理成项目、日期、区域、服务中心和服务环节下的可用材料。

### 指标必须可解释

运营不会只看一个净推荐值数字。平均评分、推荐者 / 贬损者、低分、满意率、授权率、风险服务中心和高发环节都需要一起看，并且要能解释来源。

### 报告必须可追溯

每个报告结论都要能展开原始评论，看到服务评分、推荐意愿评分、服务中心、来源问卷和服务场景。

## 6. 和已有系统的区别

### 与问卷星 / 腾讯问卷的区别

第三方问卷平台负责创建问卷、分发链接、收集答案和导出结果。本产品承接导出结果，完成字段映射、项目筛选、归因、证据选择和报告生成。

### 与 CRM 的区别

CRM 管客户档案、触达记录和生命周期。本产品关注一批反馈中的共性主题和复盘产物。

### 与 NPS 系统的区别

NPS 系统告诉团队净推荐值高低。本产品解释为什么变化，以及哪些原话、区域和服务环节支撑这个判断。

### 与工单系统的区别

工单系统处理单个问题。本产品关注项目周期内的共性、证据和运营动作。

## 7. MVP 范围

### 做

- 工作台内标准 CSV 字段说明和填写率策略。
- 标准 CSV 测试数据与本地 CSV 上传解析。
- 项目批次选择。
- 日期范围筛选。
- 区域 / 城市 / 服务中心下钻。
- 重点关注：多条好区域典型、多条风险区域典型、典型共性、证据原话和动作建议。
- 指标解释：服务评分、净推荐值、推荐者 / 贬损者、满意率、低分、负向占比、待跟进、授权率等。
- 总报告和专项报告。
- 证据原话展开。
- 原始评论查看。
- 报告复制。

### 不做

- 不自研完整问卷创建器。
- 不接第三方问卷平台 API。
- 不做登录、权限、数据库和历史报告库。
- 不处理真实姓名、手机号、车牌、VIN 或住址。
- 不替代 CRM、NPS、工单、CDP 或问卷系统。
- 不输出维修诊断或安全驾驶建议。

## 8. 核心链路

```txt
问卷 Excel / CSV 导出
-> 识别项目、时间、字段映射
-> 指定项目和日期范围
-> 查看建议报告和重点关注
-> 选择专项复盘
-> 下钻区域 / 城市 / 服务中心
-> 展开原始评论和分数来源
-> 复制报告
```

## 9. 用户端采集设计

### 采集载体

MVP 优先按第三方问卷平台设计，例如问卷星、腾讯问卷、金数据或企业现有调研工具。

后续可扩展到：

- App 内反馈页
- 服务完成短信链接
- 企微 / 社群链接
- 活动页反馈表
- 售后回访人员代录

### 问卷模板字段

- 服务评分 / 推荐意愿评分
- 服务场景：到店服务、移动服务、补能、App / OTA、活动 / 社群、其他
- 开放反馈
- 城市 / 服务中心
- 是否愿意被联系
- 可选姓名 / 联系方式
- 授权与隐私提示

### 填写率提升策略

- 表单低摩擦：首屏只保留评分、服务场景、开放反馈。
- 时机贴近：服务交付、移动服务结束、活动结束后尽快触达。
- 自动带入上下文：城市、服务中心、服务类型尽量由系统或链接参数带入。
- 明确反馈用途：告诉车主反馈会用于服务改进。
- 轻提醒：未填写时只做一次温和提醒，避免打扰。

## 10. 工作台设计

### 操作路径

1. 导入 CSV 并立即查看固定 8 模块自动复盘。
2. 合并筛选时间、项目、地区、城市和服务中心，并查看原始评论。
3. 生成模块化报告和专项输出，并通过 Agent 追问。

### 重点关注

- 好区域典型：按正向样本数、平均评分和样本量排序，提炼多条可复制服务共性和动作。
- 风险区域典型：按负向样本数、平均评分和样本量排序，提炼多条需回访、督办或复盘的共性。

### 专项复盘

| 专项 | 复盘重点 |
| --- | --- |
| 服务问题闭环 | 低分、授权联系、需复核和回访动作 |
| 满意度归因 | 平均评分、净推荐值、推荐者 / 贬损者、负向占比 |
| 区域 / 城市下钻 | 区域、城市、服务中心差异和风险聚集点 |
| 活动体验复盘 | 活动触达、现场执行、权益说明和下次优化 |
| 口碑素材与风险 | 正向素材、负向风险和回应前处理动作 |

## 11. AI 能力设计

- 输入：问卷结果、车主原话、服务评分、推荐意愿评分、来源、城市、服务中心、服务场景、项目和日期。
- 处理：服务环节归因、情绪判断、严重程度判断、主题聚类、证据选择、重点关注、报告生成。
- 输出：总报告、专项报告、重点关注、证据原话、原始评论下钻。
- 约束：不虚构车主没有提到的信息，不输出维修诊断，不给安全驾驶建议。
- 失败处理：信息不足或判断不确定时标记为需人工复核。

## 12. 当前 MVP 差距

当前原型已经能证明产品价值，但距离真实 MVP 还需要补齐：

- CSV 文件解析已接入；Excel 直读后续补齐。
- 字段映射确认。
- 导入结果确认。
- 大样本评论分页或虚拟滚动。
- 报告导出。
- LLM 报告生成接口占位。

详见 [MVP 差距检查](MVP_GAP_CHECK.md)。
