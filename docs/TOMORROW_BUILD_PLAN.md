# 原型构建计划

## 1. 当前目标

完成一个本地可运行的网页原型，证明“问卷导出 -> 项目 / 日期筛选 -> 服务复盘报告 -> 证据原话 -> 原始评论下钻”的闭环。

首版不做完整问卷系统，不做 Dashboard-first，不接真实第三方 API。

## 2. 推荐技术栈

- Vite
- React
- TypeScript
- 普通 CSS
- 标准 CSV 测试数据 + 本地上传解析
- 规则分析函数，后续可替换为 LLM 分析层

## 4. 构建顺序

### Phase 1：网页脚手架

- Vite React TypeScript。
- 单页工作台：导入区内展示标准 CSV 字段说明，报告工作台作为唯一主入口。
- 本地 dev server 可启动。

### Phase 2：标准 CSV 导入

- 提供 10-20 条标准 CSV 测试数据。
- 覆盖问卷星、腾讯问卷、App 内问卷、短信链接和企微链接。
- 上传 CSV 后解析项目名称、来源、提交时间、地区、服务中心、评分和原话。

### Phase 3：运营工作台主路径

- 导入并确认项目。
- 指定日期范围。
- 查看建议报告与评分解释。
- 选择专项复盘。
- 查看原始评论与地区下钻。

### Phase 4：重点关注与指标解释

- 做得好的服务区域 / 服务中心。
- 做得差的服务区域 / 服务中心。
- 典型共性、代表样本、处理动作。
- 指标卡展示分数来源。

### Phase 5：报告输出

- 总报告：风险、主因、下周动作、正向样本。
- 专项报告：服务问题闭环、满意度归因、区域下钻、活动复盘、口碑素材与风险。
- 每段报告可展开证据原话。
- 每条原话带服务评分、推荐意愿评分、来源问卷、服务中心。

### Phase 6：MVP 前补齐

- CSV 文件解析已接入；Excel 直读作为后续能力。
- 字段映射预览。
- 大样本列表分页或虚拟滚动。
- 导出报告。
- 更真实的 AI 分析接口占位。

## 5. 风险控制

| 风险 | 处理 |
| --- | --- |
| 做成散装工具箱 | 保持项目 / 日期 / 报告 / 下钻主路径 |
| 只剩 NPS | 扩展评分、满意率、推荐/贬损、低分、授权率、复核项等指标 |
| 结论不可追溯 | 每个结论绑定证据原话和分数来源 |
| 样本太小不真实 | MVP 前补充更大压测样本和分页能力 |
| 导入不可用 | MVP 必须补字段映射确认和 Excel 直读能力 |
| 隐私风险 | 只使用测试数据和脱敏信息 |

## 6. 完成定义

- `npm run dev` 可启动。
- 能按项目和日期筛选。
- 能生成总报告和专项报告。
- 能看到重点关注区域。
- 能下钻服务中心评论。
- 能解释关键指标来源。
- 能复制报告内容。
